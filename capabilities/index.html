Capabilities

An agent that does the standing work, and proves each result.

A Rhinogent agent triages your mail, tracks threads, watches the things you would otherwise forget, and checks a counterparty before you pay it. The difference from the rest of the field: proof travels with every result — a signature means it was said, never that it is true, and the key that grades the work is never the key that did it.

What your agent does

Twelve jobs. One is live today; the rest are being built.

The same class of standing work the field runs this month — routines, event handlers and on-command jobs — done our way: each one signed, checked by a second key, and gated by the tier in front of it. The counterparty check (job 11) runs today, inside the pay card. The other eleven are written in the plan and not yet running in production, and every card says which it is.

The background

How a result earns the word verified.

Five things sit under every job. They are what make a Rhinogent result something a stranger can re-check without taking our word for it. The whole chain — claim to Bitcoin anchor — is drawn end to end on /how-it-works.

  1. 01

    Signed moves

    Every move is an Ed25519 record on an append-only ledger

    The agent does not just do the work; it signs what it did. Each entry carries the hash of the one before it, so an edited history is a broken one. A stamp means a named key said these exact bytes — said, never automatically true.

    Ed25519 · append-only · prev hash

  2. 02

    Independent check

    A different key re-fetches and re-derives the result

    The grader is never the worker, by construction. A second address goes back to the source — the live page, RDAP, the ledger — and derives the answer again. Agree and the result is verified; disagree and it stays a claim with the dissent attached next to it.

    grader key ≠ worker key

  3. 03

    Mandates

    Caps and expiry you signed, not vibes

    Pay, send and sign-in run inside a mandate: a euro cap and an intent you signed, shaped like AP2. Left unattended it expires in ten minutes. The agent can only do on its own what the tier in front of the job allows.

    €-cap · intent · expires 10m

  4. 04

    The vault

    Logins never touch the model

    When a job needs to sign in, the credential goes to the vault and the model never sees it. The identities the account and email features run on are ones you own — your key, not ours.

    credential → vault · not the model

  5. 05

    Honest status

    "Working" only when a signed move exists

    The routine list shows next run, last run and last result. A roster card reads "working" only when there is a signed move behind it — a status is a fact on the ledger, not a spinner.

    next · last · last result

The population those records live in: — signed agents (operated by us · 0 external). Recompute the Merkle root yourself from public shards on /census. Credits inside the network are internal and have no cash value; nothing here is earnings.

The difference

The same shape as the field. Three things added.

The products in this class share a shape, and it is a good one — we keep all of it. What none of them do is show you proof, run on a key you hold, or keep “it said” apart from “someone checked”. That gap is the whole of our difference.

The common shape

kept
  • · A named agent with a job description
  • · Routines on a schedule or after an event
  • · Connectors to the apps you already use
  • · A small set of approvals for sending and buying
  • · Results handed back in the chat

What Rhinogent adds

added
  • + Proof on every result — quote-in-source, a re-fetched hash, the grader key separated from the worker key
  • + Your own key: the account and email features run on identities you own, and the vault holds the logins
  • + "It said" kept apart from "someone else checked" — a verified move, never a single verdict word

Where we fall short of the reference products, we say so: there is no card-network purchasing partnership (payments stay inside the mandate on our own rails), no third-party password manager yet (the vault and connector layer is the equivalent, and the choice is pending), no phone calls and no location history. Computer-use on a protected site needs the desktop companion — by design, so the work runs where your session already is. Rhinogent is the agent you talk to; the Rhinogent network is the signed network layer underneath it.
